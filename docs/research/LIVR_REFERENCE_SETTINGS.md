# LIVR reference settings and remaining implementation assumptions

Research date: 2026-10-11. Resolves [research issue #2](https://github.com/Shadibuchanan/SPARA/issues/2). This is a configuration investigation, not an implementation or a claim of reproducing the published result. The user accepted paper-first precedence, with relevant pinned Mirage settings filling omissions as recorded assumptions. No new dataset split, scorer, auxiliary experiment, or model download is proposed.

## 1. Paper-controlled settings

Use Qwen2.5-VL-3B-Instruct, four distinct added latent vocabulary tokens, random latent embeddings, answer-only NLL, and no helper-image supervision. Append latents to the prompt. Stage 1 blocks prompt/answer queries from image keys; latents retain causal image access. Stage 2 restores ordinary causal attention and retains the latents. These are LIVR constraints, not Mirage's autoregressive latent-generation mechanism. [LIVR v2, sections 3 and 4.2](https://arxiv.org/html/2512.21218v2#S3)

| Setting | Planning comparison value |
|---|---|
| Trainable backbone | Full language-model fine-tuning; frozen vision encoder/projector |
| Epochs | 10 Stage 1 + 10 Stage 2 |
| Optimizer | AdamW, LR `1e-5`, decay `0.01`, betas `(0.9, 0.999)`, epsilon `1e-8` |
| Batch | Per device 1, accumulation 8, effective batch 8 |
| Schedule | Separate 5% linear warmup and cosine decay per stage |
| Seed / authors' execution | 42 / single-GPU runs |

Source: [LIVR Appendix B](https://arxiv.org/html/2512.21218v2#A2). PACE-ICE is the user's compute destination. The 3B comparison target is 66%, not the 7B score. The paper does not provide a VSP-specific validation/checkpoint rule; its highest-validation and final-checkpoint rules appear under other experiment groups. [LIVR sections 4.1–4.2](https://arxiv.org/html/2512.21218v2#S4.SS2)

## 2. Applicable Mirage defaults

Every Mirage link below pins commit `53f26de2682025e146781c5b198ec93bdfe4c4d6`. These settings are accepted fallback assumptions about LIVR, not verified details of the authors' execution.

**Checkpoint and stage transition:** use the final Stage 1 model to start Stage 2; report the final Stage 2 model. Mirage's entry point supplies no evaluation dataset or best-checkpoint selection, calls `trainer.train()` and then `trainer.save_model(output_dir)`. A separate Stage 2 invocation loads model weights from Stage 1 into a new trainer, without resuming optimizer state. Adopt fresh optimizer state at the stage boundary while applying LIVR's explicit per-stage schedules. This resolves the previously open checkpoint question without creating a validation split or tuning on the test set. [main.py](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/src/main.py), [planning commands](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/README.md#training)

**Inputs:** use the released `train_direct.jsonl` and `test_direct.jsonl`, preserving row order and text. Convert `image_input` to RGB; use it with `text_input` in the user turn and `text_output` in the training assistant turn. Apply the model processor's chat template. Mirage's `place_input_image` relocates the visual placeholder to the literal `<image>` location in the question, rather than leaving a duplicated image block at the start. Exclude `image_output` entirely for LIVR; `map_desc` is scoring metadata, not model input. [task.py](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/src/task.py), [utils.py](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/src/utils.py#L53)

**Answer check:** local inspection of all 1,000 training records found no `<think>` or `<output_image>` markers in `text_output`; the first answer is `\boxed{DOWN}`. Keep these targets as released, rather than generating labels or rewriting action strings. The question already requests boxed output. Source: [pinned training archive](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/data/vsp_spatial_planning/vsp_spatial_planning.tar.gz). Earlier archive hashes/counts are recorded in the main checkout's `docs/research/LIVR_DATASET_COMPARABILITY.md`; that uncommitted note is deliberately not copied into this research branch.

**Image preprocessing:** Mirage calls `AutoProcessor.from_pretrained` and `process_vision_info` without explicit resize, minimum/maximum pixel, crop, or augmentation overrides. Preserve that default path initially; record actual processor revision, resolved image sizes and resulting visual-token counts. There is no justified paper-specific pixel cap to invent. [main.py](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/src/main.py)

**Generation/scoring:** seed 42; one record at a time in file order; `do_sample=True`, temperature `0.7`, top-p `0.9`, `max_new_tokens=1024`. The reference constructs its assistant prefix as `<|im_start|>assistant` without explicitly appending a newline, decodes special tokens, takes the last assistant segment, calls `mathruler.grader.extract_boxed_content`, then `simulate_vsp`. Save the effective generation configuration too: unspecified fields otherwise inherit model/library defaults. [test.py](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/src/test.py)

Preserve the reference's character-level `U/D/R/L` filtering, off-grid no-op, immediate hole failure and final-position goal check; no simulator action cap. Pin the boxed extractor implementation/version and probe malformed outputs before claiming evaluator parity. Mirage declares `mathruler` without a version, so the exact original extractor behavior cannot be recovered from its requirements alone. ## 3. Integration constraints and recommended implementation choices

These are engineering deductions to verify, not unpublished LIVR facts.

- **Prompt boundary:** a reasonable serialization is templated user prompt, four distinct latents, assistant prefix, answer. Fix exact placement relative to the user-end marker in a token-level fixture before training. Do not put the answer directly after the last latent: shifted next-token loss would let an image-reading latent predict the first answer token directly. An intervening image-blocked assistant prefix preserves the intended bottleneck. Mask every nonlatent text position, including template/control positions that could otherwise relay image information; retain causal and padding restrictions. Figure 2 and section 3 establish the bottleneck, but do not publish Qwen-specific token IDs or a complete serialization. [LIVR method](https://arxiv.org/html/2512.21218v2#S3.SS2)
- **Loss:** suppress labels on the input, image, latent and assistant-prefix positions. Make an explicit choice about supervising the assistant-end token/newline and preserve it in fixtures; the paper's answer-only description does not settle these tokenizer-level boundaries. Use plain answer NLL, not Mirage's cosine reconstruction objective. [Mirage trainer showing the objective that must not be copied](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/src/trainer.py)
- **Embeddings:** verify random initialization and trainability of all four added rows and saving/loading of tokenizer IDs. Appendix B's general LoRA paragraph freezes old embedding rows; the planning paragraph instead says full language-backbone fine-tuning without detailing whether this exemption includes old embeddings/output head. Record the chosen trainable-parameter manifest. Full-backbone training as in Mirage is a supported fallback, not proof of LIVR's exact row-freezing policy. [Mirage main.py trainability loop](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/src/main.py)
- **Backend and positions:** the pinned Qwen code accepts an already additive/inverted 4-D mask for eager/SDPA paths; its FlashAttention2 path is different and is not a drop-in arbitrary block-mask implementation. More subtly, the multimodal wrapper skips automatic RoPE calculation when given a 4-D mask. Compute multimodal positions from the original token IDs, image grid and 2-D padding mask before applying the bottleneck, and test cached/uncached agreement. Start with a verified eager/SDPA implementation; profile memory before any faster backend substitution. [Qwen mask code](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/transformers/src/transformers/models/qwen2_5_vl/modeling_qwen2_5_vl.py#L1464), [4-D mask/RoPE interaction](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/transformers/src/transformers/models/qwen2_5_vl/modeling_qwen2_5_vl.py#L2360)

## 4. Dependency and precision boundary

Mirage installs its modified bundled Transformers, whose version string is `4.50.0.dev0`; it is not stock Transformers with that version name. Its requirements pin only TRL (`0.15.2`), leaving torch, torchvision, qwen_vl_utils, mathruler, Pillow and others unpinned. Its training uses BF16 and fused PyTorch AdamW; these can be documented fallback implementation choices after a PACE pilot. [installation](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/README.md#installation), [version](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/transformers/src/transformers/__init__.py#L21), [training configuration](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/src/main.py)

Do not install Mirage's latent model as the LIVR implementation: it modifies the model and generation loop for a different method. Select and pin a compatible upstream Qwen implementation at implementation time, then verify the mask/position behavior against that exact revision. A complete environment lock, model/processor revision, extractor version, initialization distribution, EOS boundary, clipping behavior and precise embedding policy remain implementation assumptions to resolve and record. They do not require another experimental-design question unless a tested choice materially changes the accepted protocol.

LIVR's explicit 10+10 epochs, batch 8 and 5%-warmup/cosine schedules override Mirage README's 15+15 example, its different Stage 2 accumulation, and `main.py`'s fixed 10 warmup steps. No Mirage helper loss, compression strategy or repeated latent-pad architecture should be inherited. [planning commands](https://github.com/UMass-Embodied-AGI/Mirage/blob/53f26de2682025e146781c5b198ec93bdfe4c4d6/README.md#training)
